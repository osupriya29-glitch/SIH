# Agent Spec: Marine / PFZ Agent

## Purpose
Provides Potential Fishing Zone (PFZ) and ocean-condition data (SST, chlorophyll) for a given location/date. This is a **tool module**, not a chat-facing LLM — it's called by the Planner.

## Responsibilities
- `get_pfz_candidates(lat, lon, date, radius_km=50) -> List[PFZCandidate]`
  Returns nearby PFZs sorted by distance, with source attribution.
- `get_ocean_conditions(lat, lon, date) -> OceanConditions`
  Returns SST, chlorophyll concentration, and (if available) wave/current data for a point.
- `explain_productivity_trend(lat, lon, date_range) -> ProductivityTrend`
  Supports the "why has fish productivity declined in this region" query type — compares recent SST/chlorophyll against a baseline window and returns a structured deviation summary (NOT a free-text guess — deviations only, the Decision agent writes the prose explanation).

## Output schema — PFZCandidate
```json
{
  "zone_id": "PFZ-02",
  "lat": 16.98,
  "lon": 73.31,
  "distance_km": 18.4,
  "date": "2026-09-09",
  "sst_celsius": 28.2,
  "chlorophyll_mg_m3": 1.4,
  "source": "INCOIS PFZ Advisory (demo snapshot)",
  "confidence": "advisory"
}
```

## Output schema — OceanConditions
```json
{
  "lat": 16.98, "lon": 73.31, "date": "2026-09-09",
  "sst_celsius": 28.2,
  "chlorophyll_mg_m3": 1.4,
  "tide": {"high": ["04:12","16:40"], "low": ["10:05","22:30"]},
  "source": "..."
}
```

## Output schema — ProductivityTrend
```json
{
  "region": "Ratnagiri coastal belt",
  "baseline_window": ["2026-08-01","2026-08-31"],
  "current_window": ["2026-09-01","2026-09-08"],
  "sst_delta_celsius": 1.8,
  "chlorophyll_delta_pct": -32.0,
  "likely_factors": ["SST above seasonal norm", "chlorophyll concentration declining"],
  "source": "derived from demo/live ocean dataset, NOT a causal model"
}
```
`likely_factors` must be generated by simple threshold rules in this module (e.g. `if sst_delta > 1.5: add "SST above seasonal norm"`), not by an LLM guessing causality. Label it clearly as a correlation-based flag, not a proven cause — this matters for scientific honesty in front of ISRO judges.

## Data sourcing plan
- **DEMO mode:** ship a static `data/demo/pfz.json`, `data/demo/ocean_conditions.json` covering a handful of curated coastal points (e.g. Ratnagiri, Mangalore, Kochi) for a range of dates spanning your demo window. This must be enough to make the "killer demo query" fully work offline.
- **LIVE mode:** wrap whatever public PFZ advisory / MOSDAC / INCOIS product your DB teammate has already sourced. If no live feed is wired up in time, LIVE mode can simply be unimplemented/stubbed — DEMO mode is what you present.
- Implement both behind a common `PFZDataSource` interface (`get_pfz(lat, lon, date)`, `get_ocean(lat, lon, date)`) so switching is one env var, not a rewrite.

## Implementation notes for Antigravity
- No LLM needed inside this module. Pure Python + your demo/live data source.
- Distance calculation: haversine formula, pure function, unit-tested independently.
- Keep the module pure/stateless — no side effects, easy to unit test with fixed inputs → fixed outputs.

## Test cases
- `get_pfz_candidates` for a known demo lat/lon returns candidates sorted ascending by `distance_km`.
- `get_pfz_candidates` with `radius_km` smaller than nearest zone returns empty list, not an error.
- `explain_productivity_trend` with SST delta below threshold returns `likely_factors: []`, not a fabricated explanation.
